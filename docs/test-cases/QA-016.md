# Casos de teste — QA-016 Notas: precisão, permissão e limites

- Issue: QA-016 (P0/S3, 8 SP). Dependência: BE-015
- SPEC / critério de aceite: SPEC-PI-003 (Draft), AC-PI-003-01..06 da `main` da governança (`cca216f`); contrato core 0.1.0, recurso `/api/v1/evaluations`
- Baseline de governança: fixada em `.governance-baseline` (`governance-v0.1.0`, `379131e`); ver Q9 em `docs/questions/QA-016-perguntas.md`
- Pré-condições e dados sintéticos: usuários, projeto, membro e banca criados na ordem `users → projects → project-members → boards` pelo `tests/api/helpers/dataset.mjs`; e-mails `qa016.<run>.<papel><n>@exemplo.invalid`; dados fictícios; limpeza ao final (DELETE em ordem inversa)
- Ambiente: perfil local/test da `develop` do plataforma-backend, sem autenticação; `QA_BASE_URL` aponta para ele. Nunca produção
- Automação: `QA_BASE_URL=<url> npm run test:api` (`tests/api/notas.qa016.test.mjs`)

## Passos gerais

1. Criar a massa sintética (hook `before`).
2. Chamar `/api/v1/evaluations` com `X-Correlation-Id` único por requisição (`qa016-<caso>-<run>-<n>`).
3. Validar `status` e `code` do `application/problem+json` (nunca o texto), `correlation_id`, `fields` e os decimais **como texto** (nunca float).
4. Registrar o resultado por caso em `reports/qa-016-<run>.json` (não versionado) e remover a massa.
